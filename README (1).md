# Slot Management System

A full-stack booking slot management feature built with **ABP.io (.NET 10)** on the backend and **Angular 21** (ABP Angular Template with LeptonX theme) on the frontend. The system allows an admin to generate time slots over a date range, view next available slots by time zone, and book slots.

---

## Tech Stack

| Layer | Technology |
|---|---|
| Backend Framework | ASP.NET Core with ABP.io v10.1.1 |
| Target Framework | .NET 10 |
| ORM | Entity Framework Core 10 |
| Database | SQL Server / LocalDB |
| Time Handling | NodaTime 3.3.1 |
| Auth | OpenIddict (via ABP) |
| Frontend Framework | Angular 21 (ABP Angular Template) |
| UI Theme | LeptonX (Side Menu Layout) |
| HTTP Client | ABP `RestService` |
| Package Manager | Yarn |

## Domain Model

```csharp
public class Slot : AuditedAggregateRoot<Guid>
{
    public Instant StartInstant { get; set; }    // UTC, time-zone agnostic
    public Instant EndInstant { get; set; }      // UTC, time-zone agnostic
    public string CreationTimeZone { get; set; } // TZDB identifier used at creation
    public SlotStatus Status { get; set; }       // Available = 0, Booked = 1
}
```

Stored in SQL Server as `datetime2` (UTC) using a NodaTime `ValueConverter`.

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/app/slot/generate` | Generate slots over a date range |
| `GET` | `/api/app/slot/next-available` | Get next N available slots by time zone |
| `POST` | `/api/app/slot/book/{slotId}` | Book a specific slot by ID |

### Generate Slots — Request Body
```json
{
  "startDate": "2026-03-25",
  "endDate": "2026-03-31",
  "timeZone": "Africa/Cairo",
  "slotDuration": 30
}
```

### Get Next Available — Query Parameters
```
GET /api/app/slot/next-available?timeZone=Africa/Cairo&count=20
```

### Book Slot
```
POST /api/app/slot/book/19fd962a-acce-445c-7918-3a2038ecceda
→ 204 No Content on success
```

## Database Setup & Migrations

### Step 1: Configure the Connection String

Edit **both** files below to point to your SQL Server instance:

**`aspnet-core/src/SlotManagement.HttpApi.Host/appsettings.json`**
```json
{
  "ConnectionStrings": {
    "Default": "Data Source=(localdb)\\ProjectModels;Initial Catalog=SlotMang;Integrated Security=True;TrustServerCertificate=True"
  }
}
```

**`aspnet-core/src/SlotManagement.DbMigrator/appsettings.json`**
```json
{
  "ConnectionStrings": {
    "Default": "Data Source=(localdb)\\ProjectModels;Initial Catalog=SlotMang;Integrated Security=True;TrustServerCertificate=True"
  }
}
```

> Both files **must point to the same database**.

---

### Step 2: Apply Migrations

#### Option A — DbMigrator (Recommended)

```bash
cd aspnet-core/src/SlotManagement.DbMigrator
dotnet run
```

This will create the database, apply all EF Core migrations, and seed initial data (admin user, roles, OpenIddict clients).

#### Option B — EF Core CLI

```bash
cd aspnet-core

dotnet ef database update \
  --project src/SlotManagement.EntityFrameworkCore \
  --startup-project src/SlotManagement.HttpApi.Host
```

#### Option C — NuGet Package Manager Console (Visual Studio)

```powershell
# Open: Tools → NuGet Package Manager → Package Manager Console
$env:ErrorActionPreference = "Continue"
Update-Database -Project SlotManagement.EntityFrameworkCore -StartupProject SlotManagement.HttpApi.Host
```

> **Note:** `Update-Database` only works inside the NuGet Package Manager Console, not in a regular PowerShell terminal.

## Frontend Features

### Navigation
The **Slot Management** menu item is registered in the ABP LeptonX sidebar via `route.provider.ts` and navigates to `/slots`.

### Slot Configuration Component (`/slots`)
- Reactive form with: Start Date, End Date, Time Zone dropdown, Slot Duration
- Supported time zones (hardcoded): `Africa/Cairo`, `America/New_York`, `America/Los_Angeles`, `America/Chicago`, `Europe/London`, `Europe/Paris`, `Europe/Berlin`, `Asia/Dubai`, `Asia/Tokyo`, `Asia/Singapore`, `Australia/Sydney`
- Client-side validation:
  - All fields required
  - `startDate <= endDate` (cross-field validator)
  - `slotDuration >= 1`
- On submit: calls `POST /api/app/slot/generate`, shows total slots created or error message

### Next Available Slots Component (`/slots`)
- Time zone dropdown + count input
- Load Slots button + auto-load on time zone change
- Table showing: Local Start Time, Local End Time, Time Zone, Duration, IsBookable, Book button
- Per-slot booking with inline spinner and per-slot error display
- Booked slots update immediately in the UI without a page reload

## NodaTime Usage

NodaTime drives all backend time logic:

| Concept | NodaTime Type | Purpose |
|---|---|---|
| Date parsing | `LocalDate` | Parse `startDate` / `endDate` strings (ISO format) |
| Time zone resolution | `DateTimeZone` | Resolve TZDB identifiers e.g. `Africa/Cairo` |
| Midnight of each day | `ZonedDateTime` | Get correct local midnight (DST-safe) |
| Storage | `Instant` | UTC moment — time-zone agnostic, stored as `datetime2` |
| Display conversion | `Instant.InZone(tz)` | Convert stored instant → local time for API response |
| Current time | `SystemClock.Instance.GetCurrentInstant()` | Filter past slots, validate booking |

**Key principle:** Slots are stored as `Instant` (UTC). They are only converted to a local `ZonedDateTime` when returning them through the API.

```csharp
// Storage — time-zone agnostic
var startInstant = date.AtStartOfDayInZone(tz).ToInstant();

// Display — converted to requested time zone on read
var localStart = slot.StartInstant.InZone(requestedTz);
return localStart.ToString("yyyy-MM-dd HH:mm (z)", null);
```

**EF Core mapping** — since SQL Server doesn't natively support `Instant`, a `ValueConverter` maps it to `DateTime` (UTC):

```csharp
var instantConverter = new ValueConverter<Instant, DateTime>(
    instant => instant.ToDateTimeUtc(),
    dt => Instant.FromDateTimeUtc(DateTime.SpecifyKind(dt, DateTimeKind.Utc))
);
```

## Assumptions & Notes

- **Full day slots only:** Slots are generated from `00:00` to `23:59` in the selected time zone. Working hours are not configurable (as per the spec simplification).
- **Time zones:** The frontend uses a hardcoded list of 11 TZDB time zones. The backend accepts any valid TZDB identifier.
- **NodaTime + EF Core:** `Instant` is mapped to `datetime2` (UTC) using a `ValueConverter` — no additional NodaTime EF plugin required.
- **Slot status:** Stored as a string (`"Available"` / `"Booked"`) for readability in the database.
- **Booking returns 204:** `BookAsync` returns `Task` (void), so ABP responds with `204 No Content` — this is correct REST behavior for an action with no response body.
- **No duplicate prevention:** Generating slots for the same date range twice creates duplicates. A production system would add a uniqueness constraint.
- **DB auto-migration on startup:** `Program.cs` runs `SlotManagementDbMigrationService` on host startup as a development safety fallback.
- **Standalone Angular components:** All slot-related Angular components use `standalone: true` with direct imports — no `NgModule` wrapper needed.
- **ABP RestService:** The frontend uses ABP's built-in `RestService` instead of plain `HttpClient` to benefit from ABP's error handling, localization, and auth token injection.

## Troubleshooting

| Issue | Fix |
|---|---|
| `Invalid object name 'AppSlots'` | Run DbMigrator or `dotnet ef database update` |
| `Invalid object name 'AbpSettings'` | Both `appsettings.json` files must point to the same DB; run DbMigrator |
| `Unknown time zone identifier` | Use TZDB format e.g. `Africa/Cairo`, not `Cairo` |
| `Cannot book a slot that has already passed` | Generate slots with future dates |
| `Update-Database` not recognized | Use NuGet Package Manager Console, not PowerShell terminal |
| PowerShell blocks migration with `ErrorActionPreference` | Run `$env:ErrorActionPreference = "Continue"` first |
| CORS errors in Angular | Ensure `CorsOrigins` in `appsettings.json` includes `http://localhost:4200` |
| Angular login redirect loop | Make sure DbMigrator ran successfully and seeded OpenIddict clients |
